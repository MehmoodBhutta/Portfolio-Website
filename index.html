Workflow Sentinel

Monitoring & alerting for self-hosted n8n

Challenge

n8n has no native failure alerting that survives real-world conditions. A workflow that dies at 2 a.m. stays dead until someone notices a missing output. Existing fixes required paid SaaS or fragile custom scripts.

What was built

Three importable n8n workflows: one catches failed executions and captures the error context, one deduplicates repeated alerts so a loop of failures does not flood Slack, and one sends a daily health digest of every workflow's status. It ships as a kit with documentation and a landing page, deployable on any self-hosted instance in minutes.

Outcome

Operators get failure alerts in minutes instead of discovering breakage days later, alert fatigue is controlled by design, and the daily digest turns "is n8n okay?" from a manual check into an email glance. Released open source under MIT.

SchemaGuard

LLM output validation & self-repair in Python

Challenge

Production LLM pipelines fail on malformed output: truncated JSON, markdown fences around data, wrong types, missing fields. Retrying blindly burns tokens and still fails. Most teams hardcode string hacks per pipeline.

What was built

A Python library that validates every LLM response against a Pydantic schema, applies a transparent repair pipeline for the common failure modes (fences, truncation, type coercion), and retries with self-correcting prompts that show the model its own errors. 34 passing tests, Pydantic v2, MIT licensed, installable in one pip command.

Outcome

Pipelines built on it absorb model mistakes instead of crashing, developers stop debugging one-off parsing hacks, and every repair is logged so teams can see exactly when and why the model misbehaved. Reliability becomes a property of the infrastructure, not luck.
